## 3. Bloque 2: los defectos y cómo se corrigieron

**Ctrl+C decía `context canceled`.** Es el texto del error
`context.Canceled` de Go: correcto para un programador, inútil para un
usuario. Archivo `internal/runner/runner.go`: el tipo `interrupted` envuelve
el error original.

```go
type interrupted struct{ cause error }

func (e interrupted) Error() string { return "interrupted (Ctrl+C)" }
func (e interrupted) Unwrap() error { return e.cause }
```

`Error()` decide cómo se ve; `Unwrap()` permite que `errors.Is(err,
context.Canceled)` siga siendo verdadero. Así se cambia el mensaje sin perder
qué error es. El test `TestRunStopsWhenCancelled` comprueba las dos cosas.

**`Steps 1-1 were completed`.** Archivo `cmd/caratcore/install.go`, función
`stepRange`: si el rango es de un paso, escribe `Step 1 was`. Tiene su test
en tabla (`TestStepRange`).

**El color de Compose con `NO_COLOR`.** `sudo` limpia el entorno, así que
`NO_COLOR` no llega a `docker compose`. Se decidió dejarlo: no es texto de
CaratCore, y pasarle `--ansi never` haría que el plan dependiera de la
terminal, mezclando núcleo e interfaz (D2).

## 4. Bloque 3: rehacer una release sin publicar (D28)

Los defectos aparecieron con la etiqueta `v0.2.0` ya subida y el borrador
creado. Como nadie lo había visto, D28 dice qué hacer:

1. Borrar el borrador (en la web de GitHub).
2. Borrar la etiqueta: `git tag -d v0.2.0` y `git push origin --delete v0.2.0`.
3. Corregir, con tests, y hacer commit.
4. Etiquetar de nuevo y subir la etiqueta: el workflow
   `.github/workflows/release.yml` crea otro borrador.
5. Repetir **solo** los casos afectados (checksum, M3, M4) con el binario
   nuevo.
6. Publicar y comprobar la descarga pública.

Una etiqueta publicada **no** se rehace nunca: alguien puede haber descargado
ese binario. Por eso existe el borrador.

`--guided` y `uninstall` casi sin esfuerzo), un paquete por responsabilidad,
solo librería estándar y un proceso de release que encuentra defectos antes

**La deuda principal: D23.** Para saber si un `compose.yaml` fue editado,
CaratCore lo compara con lo que escribiría **esta** versión. Cuando una
versión nueva cambie la imagen, los servicios desplegados con la anterior
parecerán editados a mano (en U8 ya se vio: "edited by hand, or written by
another version"). Antes de poder actualizar servicios, CaratCore debe guardar
al desplegar un pequeño archivo con la versión y el hash de lo que escribió.

## 6. Glosario

- **Borrador (draft release)**: release de GitHub sin publicar; solo la ve el
  dueño y sus enlaces de descarga no son públicos.
- **`context.Context`**: valor de Go que lleva la señal de "cancela" (aquí,
  Ctrl+C) a las funciones que esperan.
- **Envolver un error (wrap)**: crear un error que contiene otro; `Unwrap`
  lo devuelve y `errors.Is` / `errors.As` lo recorren.
- **`env_reset`**: opción de sudo que borra casi todas las variables de
  entorno antes de ejecutar el comando.
- **Instantánea (snapshot)**: copia del estado de una VM a la que se puede
  volver.
- **Purgar**: aquí, borrar además los datos del servicio.
